# Coffee Compare デザインガイドライン v1.0

作成日：2026-09-19
参考：
- [SmartHR Design System](https://smarthr.design/) — アクセシビリティ基準・デザイントークン・ライティング・コンポーネント設計の考え方
- [Apple Human Interface Guidelines: Designing for iOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios) — タップ領域・タイポグラフィ・ナビゲーション・セーフエリア

本ガイドラインは要件定義書（REQUIREMENTS.md）§3 の最重要ルールを視覚言語に落とすもの。**「順位付けしない」「差分を捏造しない」「入力負担を減らす」を UI で体現する。**

---

## 1. デザイン原則

1. **比較が主役**：最も目立つ要素は常に「基準 vs 今回」の差分。装飾は差分の理解を助けるためだけに使う。
2. **押しつけない**：数値が大きい＝良い、という表現（ランキング・総合点・メダル）を使わない。評価は本人の相対的な好みのみ。
3. **正直な空欄**：不明値は「—（不明）」と表示し、0 やダミー値で埋めない。捏造された差分を見せない。
4. **片手・キッチン**：濡れた手・片手操作を想定。主操作は画面下部・大きなタップ領域・最少タップ数。
5. **静かな画面**：抽出中に気を散らせない。演出は保存完了・基準更新など「区切り」の瞬間に限定する。

## 2. カラー

温かいオフホワイト＋濃茶の文字＋アクセント 1 色。参考画像の青系は転用しない。

### 2.1 トークン（CSS カスタムプロパティ）

| トークン | 値 | 用途 |
|---|---|---|
| `--color-bg` | `#F7F3EE` | 画面背景（温かいオフホワイト） |
| `--color-surface` | `#FFFFFF` | カード・シート |
| `--color-surface-sub` | `#EFE9E1` | 区切り・入力欄背景 |
| `--color-text` | `#3B2E25` | 本文（濃い茶） |
| `--color-text-sub` | `#7A6A5C` | 補助テキスト |
| `--color-accent` | `#B3541E` | 主ボタン・リンク・強調（焙煎ブラウンオレンジ） |
| `--color-accent-strong`| `#8C3D0F` | 押下・ホバー |
| `--color-diff-bg` | `#FBEFE3` | 変更行の淡い背景 |
| `--color-diff-text` | `#8C3D0F` | 差分テキスト（−2℃ 等） |
| `--color-new-bg` | `#EEF2EA` | 「新たに入力」行の背景（差分と別色） |
| `--color-baseline` | `#5C7A5E` | 「基準」バッジ・基準側の識別 |
| `--color-danger` | `#B3402E` | 削除・破棄・エラー |
| `--color-border` | `#E3DACF` | 罫線 |
| `--color-focus` | `#1A6AA8` | フォーカスリング（背景と十分なコントラスト） |

### 2.2 使用ルール

- 本文 `--color-text` on `--color-bg`／`--color-surface` はコントラスト比 4.5:1 以上（WCAG AA）。アクセント上の白文字も 4.5:1 以上を維持する。
- **色だけで意味を伝えない**（SmartHR アクセシビリティ方針）。差分は色＋「−2℃」等のテキスト、基準は色＋「基準」ラベル、必ず併記。
- 意味色は 4 つまで：アクセント（操作）／差分（変更）／新規入力／危険。それ以外の彩色はしない。
- ダークモードは MVP 対象外（将来トークン差し替えで対応できるよう、色は必ずトークン経由で参照）。

## 3. タイポグラフィ

- フォント：システムフォントスタック。`-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Noto Sans JP", sans-serif`（iOS では SF/ヒラギノ、HIG 推奨のシステムフォント優先）。
- 本文 16px（1rem）基準。**px 固定せず rem** で指定し、ブラウザの文字サイズ設定・Dynamic Type 相当の拡大を妨げない。

| 用途 | サイズ | ウェイト |
|---|---|---|
| 画面タイトル | 1.375rem (22px) | 700 |
| セクション見出し | 1.0625rem (17px) | 600 |
| 本文・入力値 | 1rem (16px) | 400 |
| 比較表の値 | 1rem | 500 |
| 差分・バッジ | 0.8125rem (13px) | 600 |
| 補助・注釈 | 0.8125rem (13px) | 400 |

- 数値（温度・時間・g/ml）は `font-variant-numeric: tabular-nums` で桁を揃える（比較表の視線移動を安定させる）。
- 行間：本文 1.6、表 1.4。長文メモは表外に展開表示（要件 §6C）。

---

## 4. レイアウト・スペーシング

- 基準幅 360px〜。コンテンツ最大幅 480px、中央寄せ（デスクトップでもスマホレイアウトを維持）。
- スペーシングは 4px グリッド：4 / 8 / 12 / 16 / 24 / 32。
- セーフエリア対応：`env(safe-area-inset-*)` を下部ナビと固定ボタンに適用（HIG）。
- カード：角丸 12px、影は `0 1px 3px rgba(59,46,37,.08)` の 1 段のみ。枠線は `--color-border`。
- 比較表：`項目名｜基準｜今回` の 3 列。360px で横スクロールなし。項目名列は 0.8125rem・`--color-text-sub`。
- 文字拡大（200%）時は比較表を「項目ごとの縦ペア表示」へ切り替える（メディアクエリ＋文字サイズ検知ではなく、コンテナ幅ベースで折り返す設計）。

## 5. ナビゲーション

- 下部タブバー 3 つ：**淹れる／くらべる／設定**（HIG のタブバー慣習。5 個以内・現在地明示）。
- タブはアイコン＋ラベル併記。アイコンのみにしない。
- フロー画面（比較の準備→抽出→評価）はタブバーを隠さず、戻る導線を左上に置く。破棄を伴う戻りは確認ダイアログ。
- モーダルは「基準更新の確認」「破棄確認」「復元確認」など、取り返しに関わる操作のみに使う。

## 6. コンポーネント

### 6.1 ボタン

- 主ボタン：`--color-accent` 塗り、白文字、高さ 48px、角丸 10px、幅いっぱい。1 画面 1 つまで。
- 副ボタン：枠線＋アクセント文字。
- テキストボタン：リンク色。破棄系は `--color-danger`。
- **タップ領域は最小 44×44 CSS px**（HIG）。視覚サイズが小さくても padding で確保。
- 無効状態は透明度でなく色＋説明文（なぜ押せないか）で示す。

### 6.2 入力

- 選択式（セグメント・チップ）を最優先。自由入力は補助。
- 数値入力は `inputmode="decimal"`／`"numeric"` を指定しモバイルで数値キーボードを出す。
- 各入力に「不明・未計測」トグルを併設。ラベルは入力欄の上（プレースホルダをラベル代わりにしない）。
- 単位（g/ml/℃/秒）は入力欄の右に常時表示。
- エラーは入力欄の直下に赤テキスト＋アイコン。色だけに依存しない。

### 6.3 比較表（中核コンポーネント）

- 同じ項目は同じ行。左「基準（日付）」右「今回」。
- 変更行：`--color-diff-bg` 背景＋右セルに差分バッジ（例「−2℃」「+15秒」）。
- 「新たに入力」行：`--color-new-bg` 背景＋「新規」バッジ。**差分数値は出さない**。
- 不明値：「—」＋「不明」。斜体にしない（可読性）。
- 意図した変更（planned）は行頭に ●、観測された差（actual）は ○ ＋注記。凡例を表の上に置く。

### 6.4 バッジ・ラベル

- 「基準」バッジ：`--color-baseline` 枠＋文字。
- 「未評価」バッジ：グレー枠。未評価を「違いが分からない」と混同する表示をしない。
- 相対評価の表示は本人の言葉のまま：「基準が好き」「今回が好き」「違いが分からない」。

### 6.5 空状態

- イラスト大でなく、1〜2 行の説明＋次の 1 アクション。例：「まだ一杯もありません。最初の一杯を作りましょう。［最初の一杯を作る］」

---

## 7. ライティング（SmartHR ライティングガイド準拠の方針）

- 文体：「です・ます」。命令形にしない（「入力してください」→「入力できます」を基本、必須時のみ「〜してください」）。
- ボタンは動詞で終える：「この条件で淹れる」「淹れ終わった」「次回の基準にする」。
- 断定しない：「苦味が強くなりました」ではなく「苦味：基準より強い（あなたの感想）」。
- 専門用語には初出時に短い説明（例：総抽出時間の定義文）。
- 数値・単位は半角、単位は数値の直後（92℃、15g）。日付は「2026/09/19」形式。

---

## 8. アニメーション

- 用途を 3 つに限定：差分行の軽いフェード強調／カード・画面切替（150–200ms）／基準更新完了の短い演出（300ms 以内）。
- `prefers-reduced-motion: reduce` で全て無効化し、機能は動きなしで完結する。
- 演出完了を待たせない（操作ブロックしない）。蒸気・抽出などの長尺演出・3D は使わない。

---

## 9. アクセシビリティ チェックリスト

- [ ] テキストコントラスト AA（4.5:1）以上。UI 部品・差分バッジは 3:1 以上。
- [ ] 色以外の手段（テキスト・アイコン・ラベル）で全情報を伝達。
- [ ] タップ領域 44×44px 以上。
- [ ] キーボード操作可能・フォーカスリング常時可視（`--color-focus` 2px）。
- [ ] フォーム要素に label 関連付け。比較表に適切な `<th scope>`。
- [ ] 相対評価・バッジに読み上げラベル（aria-label）。
- [ ] 200% 文字拡大で情報欠落なし（縦ペア表示へ切替）。
- [ ] `prefers-reduced-motion` 追従。
- [ ] iPhone Safari 実機でキーボード表示時に下部ボタンが隠れないか確認。

## 10. 実装メモ

- 全トークンは `src/ui/styles/tokens.css` に定義し、コンポーネントからは必ず `var(--...)` で参照する。
- コンポーネントは `Button` `Card` `Badge` `Field` `SegmentedControl` `CompareTable` `TabBar` `Dialog` `EmptyState` を共通化し、画面側で直接色・サイズを指定しない。
- クラス命名は BEM 風（`.compare-table__row--changed`）。
