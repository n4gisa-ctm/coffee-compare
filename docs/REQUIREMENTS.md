## 1. プロダクトの核

### 1.1 一文で

**「一杯ずつ比べて、自分の正解を見つける。」**
記録アプリではなく比較アプリ。淹れたコーヒーの条件と味を「基準の一杯」と比べ、自分好みの一杯を再現・更新していくためのツール。

### 1.2 解決する課題

自宅でハンドドリップを楽しみ、条件を少しずつ変える人が抱える課題：

1. 前回の条件・感想を忘れる。
2. 複数の条件を同時に変えてしまい、何が効いたのか分からなくなる。
3. 「あのとき美味しかった一杯」の条件へ戻れない。

### 1.3 競合との違い（ポジショニング）

| 観点 | 一般的なコーヒー記録アプリ | 本ツール |
|---|---|---|
| 主目的 | 記録を残す・蓄積する | **2杯を比較して次の一手を決める** |
| ホーム画面 | 記録一覧・カレンダー | **「基準と比べて淹れる」開始ボタン** |
| 評価 | 絶対スコア（5段階等） | **相対評価（基準が好き／今回が好き／分からない）** |
| 成功指標 | 記録件数・継続日数 | **2杯目で差分と好みが分かること** |
| 順位付け | 総合点ランキング | **しない**（味の数値が大きい＝良いではない） |

参考にした比較系アプリ（学校見学比較アプリのストア画像 7 枚）から取り入れる点・見送る点は §9 に整理。要点：**「同じ項目を同じ行に並べる比較表」「差分のハイライト」「一覧と比較の役割分離」は採用**、「複数対象の採点・総合点・順位付け・PDF 出力」は不採用または将来検討。

### 1.4 価値の成立条件

2 杯目を淹れた時点で、次の 3 つがユーザーに分かること：

1. どこを変えたか（意図した変更と、実際に生じた差の区別を含む）
2. どちらが好きか
3. 次に何を再現・変更するか

## 2. スコープ

### 2.1 確定事項

- 比較を中心に構成する。コアループ＝**基準 → 複製 → 変更点選択 → 抽出 → 比較 → 相対評価 → （明示操作で）基準更新**。
- MVP はスマートフォン対応 Web アプリ。最終的に iOS アプリ化したい（Capacitor 第一候補）。
- フロントエンドは React 系（React + TypeScript）。
- 参考画像の意匠をそのまま複製しない。情報構造のみ参考にする。
- GitHub 公開・Vercel デプロイを最終成果物とする。

### 2.2 採用（初期実装方針）

- React + TypeScript(strict) + Vite。クライアント完結（専用バックエンドなし）。
- ハンドドリップ専用。同じ豆（購入単位）×同じ器具×同じミルを比較単位（グループ）とする。
- ログインなし。IndexedDB に端末内保存。JSON バックアップ／復元あり。
- 抽出時間は手入力（分・秒、未計測可）。計測タイマーは MVP 対象外。
- 課金・広告・クラウド同期は MVP 対象外。

### 2.3 MVP 機能一覧

| 機能 | MVP | 備考 |
|---|---|---|
| 豆と器具の登録（グループ作成） | ✅ | 手入力のみ。外部データ連携なし |
| 初回の一杯登録 → 明示操作で基準化 | ✅ | 初回に比較結果は作らない |
| 基準の複製・変更点選択 | ✅ | 変更前後と差分を表示 |
| 基準と今回の 2 杯比較 | ✅ **最優先** | 同じ項目を同じ行位置に並べる |
| 相対評価・基準更新 | ✅ | 自動上書きなし。更新履歴を保持 |
| 過去の完成済み 2 杯の閲覧比較 | ✅ | 同一グループ内。新規評価の作成は不要 |
| 抽出時間の入力・差分表示 | ✅ | 未計測を許可し「不明」と表示 |
| 下書き保存・再開 | ✅ | 進行中の比較は全体で 1 件 |
| バックアップ／復元・全削除 | ✅ | JSON、全置換方式、事前検証 |
| ストップウォッチ／工程タイマー | ❌ | §10 の判断基準で後付け検討 |
| ログイン・クラウド同期 | ❌ | 将来候補 |
| 課金・広告・PDF・SNS・AI 提案 | ❌ | 比較体験の検証後 |
| エスプレッソ等の他方式 | ❌ | 入力設計が別物 |

## 3. 最重要ルール（実装の判断基準）

1. 主操作は「記録する」ではなく「**基準と比べて淹れる**」。
2. 「基準の一杯」と「今回」を混同しない。基準の日付を常に明示する。
3. 1 条件変更を推奨するが強制しない。複数変更・変更なし（同じ条件でもう一度）も許可。
4. **味の数値が大きい＝良い、ではない**。酸味・苦味・濃さと好みは別物。順位付けしない。
5. 相対評価は「基準が好き／今回が好き／違いが分からない」。後回し（未評価保存）可。
6. 「今回が好き」でも基準は自動更新しない。「次回の基準にする」の明示操作でのみ更新。
7. 過去の比較は不変。基準変更・名称変更で過去の比較対象をすり替えない。
8. 空欄は「不明」。0 や前回値に自動変換しない。差分の捏造をしない。
9. 比較結果は本人の感想。原因や科学的優劣を断定する文言を UI に置かない。
10. 入力負担を最小に。複製＋選択式を基本にし、長文・全項目入力を強制しない。

## 4. 比較の単位とデータ入力

### 4.1 比較グループ

- 1 グループ＝豆の購入単位（袋）＋抽出器具＋ミル。
- 同じ銘柄の買い直しは新しい袋（新グループ）。既存条件のコピー可。過去の袋との直接評価は対象外。
- 器具・ミルの変更は新グループへ案内（異なるミルの「10 クリック」を同一視しない）。
- 各グループは現在の基準 brewId を 1 つ持つ。複数グループ保存可。

### 4.2 一杯の入力項目

**必須**：豆の呼び名・器具の呼び名（グループ作成時）／豆量 g／総注湯量 ml。日時は現在日時が初期値。

**任意**：焙煎度、購入日・焙煎日、ミル名、挽き目（自由記述可：例 C40／24 クリック）、湯温 ℃、総抽出時間、蒸らし時間、注ぎ方メモ、味のひとこと。

**入力ルール**：

- 計れない項目は「不明・未計測」。初期値で埋めない。
- 総抽出時間の定義を画面に明記：「最初にお湯を注いでから、ドリッパーを外すまで」。
- 総注湯量 ≠ 完成した飲料量。ml と g を無説明で混在させない（g 入力は将来検討）。
- 目標値と実測値を区別する（§4.3）。
- バリデーション：数値必須項目は正数、温度 0〜100℃、時間 0 以上の整数秒。異常値は確認表示。小数の丸めをテストする。
- 豆量／湯量から比率 1:x を参考表示（派生値であり、変更項目として数えない）。

### 4.3 変更の分類（本ツールの独自性の核）

| 分類 | 意味 | 例 |
|---|---|---|
| plannedChanges | 意図して変えた項目 | 92℃ → 90℃（−2℃） |
| actualDifferences | 抽出後に観測された差 | 挽き目を変えたら総時間も 15 秒延びた |
| 新たに入力 | 前回「不明」だった項目に今回値を入れた | 不明 → 90℃（差分は表示しない） |

- 変更点の選択肢：挽き目／湯温／豆量／湯量／目標抽出時間／蒸らし時間／注ぎ方メモ／**同じ条件でもう一度**。
- 選択した項目を最初に編集可能にし、他の項目は基準値を引き継ぐ。「ほかの条件も変更」で追加可。
- 意図した変更と観測された差を別の見た目で表示し、「ルール違反」と扱わない。

## 5. 利用フロー

### 5.1 初回

```
グループ登録（豆・器具） → 初回条件の入力 → 淹れる → 実際の条件を確認
→ 一杯を保存 → 「この一杯を基準にする」（明示操作）
```

- 初回に比較結果を作らない。「次の一杯から比較できます」と案内。
- 飲む前の下書きは基準にできない。

### 5.2 2 杯目以降（コアループ）

```
グループ選択 → 基準を複製 → 変更点を選ぶ → 条件一覧を見ながら淹れる
→ 実際の条件を確認（実測修正欄） → 基準 vs 今回の比較 → 相対評価
→（任意）「次回の基準にする」
```

- 評価は「今回が好き」を 1 タップするだけでも完了できる。
- 任意で酸味・苦味・濃さを「弱い／同じくらい／強い／分からない」で入力（基準に対する相対、絶対スコアではない）。
- 「あとで比べる」＝未評価保存。ホームに再開導線。未評価から基準更新はしない。
- 過去の完成済み一杯を基準に設定する操作は、確認ダイアログ付きで別途許可。

## 6. 画面要件

下部ナビは 3 タブ：**淹れる／くらべる／設定**（比較系アプリの「一覧・比較・設定」構成を踏襲しつつ、ホームを一覧ではなく比較開始にする）。

### A. ホーム「淹れる」

- 現在のグループ、基準の日付・主要条件・ひとことをカード表示。
- 主ボタン「この一杯と比べて淹れる」（初回のみ「最初の一杯を作る」）。
- 下書きがあれば「途中の比較を再開」を最優先表示。新規開始時は破棄確認。
- 未評価の一杯への導線、グループ切替。記録件数・連続日数の誇示は置かない。

### B. 比較の準備／抽出中

- 意図して変える項目と差分（例「92℃ → 90℃（−2℃）」）を上部に要約。
- 変更しない条件も一覧で確認できる。ボタン「この条件で淹れる」→「淹れ終わった」。
- 抽出中は条件を見やすく固定。演出は最小限。自動で抽出完了を判定しない。タイマー・通知なし。
- 抽出後に「実際には条件が変わった」修正欄。予定値を実測値として自動確定しない。

### C. 比較画面（中核）

- 左「基準」右「今回」の 2 列。日付と比較対象を明示。
- 上部に意図した変更の要約 → 条件 → 感想の順。**同じ項目は同じ行**。
- 変更行のみ淡い背景＋差分テキスト（「−2℃」等）で強調。色だけに依存しない。
- 表の下に相対評価 3 択。未選択保存＝未評価。
- 詳細感想は展開式。基準更新ボタンは評価保存後に表示。
- 過去 2 杯の閲覧比較は左「比較元」右「比較先」。その組合せに対する保存済み評価のみ表示（他の組合せの評価を流用表示しない）。

### D. 比較履歴「くらべる」

- 1 カード＝日付・変更点・本人の選択。**平均点や順位は出さない**。
- グループ内の完成済み 2 杯を選んで横並び閲覧。
- 「現在の基準」バッジ。基準更新前の履歴も残す。
- 空状態（記録なし／1 杯のみ／未評価あり）を設計する。

### E. 設定（豆・器具／データ）

- グループ追加・編集・アーカイブ（物理削除は提供しない。全削除のみ確認付き）。
- バックアップ出力／復元／全削除、保存先の説明（「この端末のブラウザに保存」）。
- 完了済み一杯の訂正は上書きせず訂正版レコードを作成。既存比較は当時の値を維持し、訂正済み表示から最新版へ移動できる。

## 7. データ設計

| モデル | 主な項目 |
|---|---|
| BeanBatch | id, name, roastLevel?, purchasedAt?, roastedAt? |
| BrewGroup | id, beanBatchId, brewerName, grinderName?, baselineBrewId?, archivedAt? |
| Brew | id, groupId, brewedAt, actualParameters, note?, revisionOf? |
| Comparison | id, groupId, baselineBrewId, trialBrewId, plannedChanges, preference(nullable), relativeTaste, comparisonMode, evaluatedAt? |
| Draft | id, groupId, baselineBrewId, baselineSnapshot, plannedParameters, actualParameters, stage, updatedAt |
| BaselineChange | id, groupId, fromBrewId(nullable), toBrewId, changedAt |
| Settings | schemaVersion, 表示設定, 最終バックアップ日時 |

**整合性ルール**：

- 比較開始時に基準 ID と条件をスナップショット固定。進行中に別画面で基準が変わっても比較元は不変。
- 完了した Brew は不変。訂正は revisionOf を持つ新レコード。
- 相対味評価は Comparison に属する（Brew の絶対値にしない）。A→B の評価を B→C に流用しない。
- comparisonMode：remembered（記憶との比較、初期値）／sideBySide(同時飲み比べ)。精度保証には使わない。
- 1 Comparison に 1 trialBrew。保存連打の重複防止。Brew・Comparison・Draft の更新は 1 トランザクション。基準更新と BaselineChange も同様。

## 8. 保存・復元・例外処理

- 初回に「この端末・ブラウザに保存されます。他の端末へ自動同期されません」と説明。
- 保存成功後のみ成功表示。失敗時は入力を保持し再試行可能。
- JSON バックアップ：schemaVersion・全モデル・出力日時を含む。外部送信しない。
- 復元：形式・型・参照 ID・重複 ID・バージョンを事前検証。不正なら既存データを一切変更しない。全置換方式で、件数プレビュー＋既存データのバックアップ案内＋明示確認を挟む。
- 別タブ更新の競合は revision で検知し再読み込み案内。無言上書きしない。
- 戻る・再読み込みで下書き復元。保存不能時は離脱警告。
- オフラインでも開いている画面はローカル操作可能。オフライン再起動保証（PWA キャッシュ）は MVP 必須にしない。
- 外部 API キー・外部画像・スクレイピング・解析サービス送信は行わない。

## 9. 競合リサーチの適用（学校比較アプリのストア画像）

| 参考にする点 | 本ツールでの扱い |
|---|---|
| カードで対象を識別、短い価値訴求コピー | 採用（グループ・一杯カード） |
| 同じ評価項目を同じ行に配置した比較表 | 採用（比較画面の中核） |
| 差分・最安値のハイライト | 差分ハイライトのみ採用。「最小＝最良」の扱いはしない |
| 一覧（学校一覧）と比較（くらべる）の役割分離 | 採用（くらべる＝履歴＋閲覧比較） |
| 淡い背景・白カード・少ないナビ | 採用（配色は独自。§DESIGN_GUIDELINES） |
| 選択式入力・評価軸の編集 | 選択式は採用。軸の自由編集は将来 |
| 星の総合点・ランキング・3 件以上の横長表・PDF 出力 | **不採用**（2 杯比較に限定、順位付けしない、PDF は将来） |

## 10. タイマーの判断（据え置き）

- MVP 必須：総抽出時間の手入力・比較・未計測表示。
- 対象外：カウントダウン、通知、注湯ガイド、音声、レシピ配信。
- 次段階候補：開始／停止のみの任意ストップウォッチ（停止値を転記し手修正可）。
- 後付け判断は利用テストで「計測・転記が面倒で比較をやめる」「外部タイマー往復で入力漏れ」が繰り返し出た場合のみ。競合にあるからという理由では追加しない。
- 実装時は開始時刻と現在時刻の差で算出（再描画回数に依存しない）。バックグラウンド動作は Web で保証しない。

## 11. 技術構成

- React + TypeScript(strict) + Vite。CSS は素の CSS（カスタムプロパティでトークン管理）＋必要箇所のみ SVG。
- レイヤ構成：
  - `domain`：型、差分判定、比率計算、基準更新ルール。React／ブラウザ API 非依存。
  - `application`：比較開始・保存・評価・基準更新・復元のユースケース。
  - `repositories`：保存先インターフェース。
  - `infrastructure`：IndexedDB 実装、JSON 入出力。
  - `ui`：React 画面。
- テスト：domain／application の単体テスト（Vitest）。主要フローのブラウザ確認。
- IndexedDB はサイトデータ削除で失われうる。無期限保存を保証しない旨を UI に明記。
- 将来の iOS 化は Capacitor 第一候補。Web の保存領域は自動移行しない前提で、JSON 出力を移行入口にする。
- デプロイ：Vercel（静的ビルド）。リポジトリは GitHub 公開。

## 12. 受け入れ条件

1. 初回の一杯を保存し基準にできる。初回に架空の比較結果がない。
2. 基準 92℃ → 90℃ の変更で「−2℃」を表示し、他条件は引き継がれる。
3. 不明 → 90℃ は「新たに入力」となり差分を捏造しない。
4. 挽き目を意図的に変え実測時間も変わった場合、意図と観測が区別できる。
5. 複数変更・変更なしを保存でき、適切な注意が表示される。
6. 「今回が好き」だけでは基準が変わらず、明示更新でのみ変わる。
7. 基準更新後も過去比較の条件・対象・相対感想が不変。
8. 未評価保存から再開できる。未評価≠「違いが分からない」。
9. 任意の 2 杯の閲覧比較で、別の組合せの相対評価を表示しない。
10. 完了一杯の訂正後も既存履歴が残り、訂正前後が分かる。
11. 保存連打・途中離脱・再読み込みで重複・参照切れが発生しない。
12. バックアップ→全削除→復元で基準・比較・履歴が一致。不正 JSON は既存データを壊さない。
13. 360px 幅で 2 杯の主要条件が横スクロールなしで読める。文字拡大・動き削減でも操作可能。
14. iPhone Safari・Android Chrome・デスクトップ主要ブラウザで主要フローを確認。実機未確認項目は完了報告に明記。

## 13. 開発順序

1. ドメイン型・保存形式・比較／基準更新ルール＋単体テスト。
2. 初回登録→複製→変更→比較→評価→基準更新を簡素な UI で一周。
3. 履歴・過去 2 杯比較・下書き・訂正・保存エラー・バックアップ／復元。
4. デザインガイドライン適用（カード・比較表・軽い演出）。
5. 実機テスト・少人数利用テスト。GitHub 公開・Vercel デプロイ。
